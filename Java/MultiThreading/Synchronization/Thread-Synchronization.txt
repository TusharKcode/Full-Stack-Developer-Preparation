It used to control the access of multiple threads to shared resources to avoid data inconsistency
    - ensures that only one thread executes a critical section at a time, preventing race conditions.
    - Achieved using synchronized keyword, locks, and other concurrency utilities.
    - Helps prevent thread interference and memory consistency errors.
    - Supports coordination using methods like wait(), notify(), and notifyAll().

    => Examples:    
        -> If two computers send print jobs simultaneously, the printer might mix their outputs and that 
            leads to invalid results.
        -> Similarly, threads accessing the same resource without coordination can produce inconsistent data.

=> Thread Priorities:   
    It determine the execution order, allowing higher-priority threads to preempt lower ones and access 
        resources first
    When threads of equal priority compete for the same resource, conflicts can lead to inconsistent or 
    erroneous outcomes.

=> Mechanisms for Thread Synchronization
    - Thread synchronization ensures only one thread executes at a time while others wait.
    - It helps prevent thread interference and data inconsistency issues.
    - Implemented using locks/monitors in Java.
    - A monitor (object lock) allows only one thread to access a resource at a time.
    - When a thread acquires a lock, other threads are blocked until the lock is released.
    - Other threads remain in a waiting state until the current thread exits the critical section.

=> Types:   
    -> Mutual Exclusion: 
        - While sharing any resource, this will keep the thread interfering with one another i.e. mutual 
            exclusive.
        - Achieve from: 
            Synchronized Method: using the 'synchronized' keyword, code written inside the method thread-safe 
                                    so that no other thread will execute while the resource is shared.

            Synchronized Block: If we declare a block as synchronized, only the code which is written 
                                inside that block is executed sequentially not the complete code.
                                Syntax: synchronized (object reference) {}

            Static Synchronization: synchronized method is declared as "static" which means the lock or 
                                    monitor is applied on the class not on the object, only one thread will 
                                    access the class at a time.

        - When a class has both synchronized and static synchronized methods they can run parallel
            as those two methods require different locks.


    -> Inter-Thread Communication
        - known as Cooperation in Java.
        - enables threads to coordinate their execution by signaling each other during runtime
        - used when multiple threads depend on shared resources or need to work in a specific sequence.
        - avoid busy waiting and improves resource utilization
        
        - "Polling": process of repeatedly checking a condition in a loop until it becomes true.
                        used when one thread waits for another to produce or update data.

                    Wastes CPU cycles due to continuous condition checking
                    Reduces efficiency and slows down overall execution
                    Keeps the thread busy instead of allowing other tasks to run
            
            Handling this: using built-in communication methods, defined in the Object class and must be 
                            used within a synchronized context. 
                - wait(): Releases the lock and puts the thread into a waiting state until notified
                            (public final void wait() throws InterruptedException)
                            Exceptions: InterruptedException, IllegalMonitorStateException
                            
                - notify(): Wakes up one waiting thread (does not release the lock immediately)
                - notifyAll(): Wakes up all waiting threads on the same object

            Producer-Consumer Problem:  
                - involves two threads where one (producer) adds data to a shared queue
                - other (consumer) removes data from it.
                - Proper coordination is required to ensure the producer doesn’t add when the queue is full
                    & consumer doesn’t remove when it’s empty.
                - ses wait(), notify(), and notifyAll() for synchronization
