Asynchronous events occur at different times, independently from each other.

=> "asynchronous" refers to tasks that run in the background, independently from the main flow of 
    the program.
    - they don’t block the execution of the main program.

    - helpful for tasks that may take a long time to run, such as fetching data from a remote server, 
        processing large files, handling user input, and performing complex calculations.

=> Everything is sequential and predictable. Each line is completed before the next one starts. 
    This type of JavaScript program is known as single-threaded.

    -> A thread is a unit of execution within a process. It’s like a separate flow of control within the 
        program.
    -> In synchronous programming, threads execute sequentially, one after the other.
        If a thread is blocked, like waiting for user input, the entire process is blocked until the 
        thread is completed.

-> JavaScript is single-threaded and uses an event loop to handle asynchronous operations.
    - This allows the program to continue executing other tasks while waiting for asynchronous operations, 
        such as network requests or timers, to complete without blocking the main thread.

    - Asynchronous programming often involves callbacks, promises, or async/await to handle 
        non-blocking operations.

->  A Promise is an object that represents the eventual completion (or failure) of an asynchronous process 
    and its value.
    - The value of a promise is not known when the promise is created.
    - It’s only known when the asynchronous process is completed. 

    Example: the process of fetching data from a remote API for your web application may take some time. 
        Meanwhile, you want your users to have a nice user experience.

        When the process is completed, the promise will contain the data that was sent back by the API, 
            so the application can handle it or render it appropriately when it’s available.
