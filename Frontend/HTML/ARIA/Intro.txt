"WAI-ARIA" stands for Web Accessibility Initiative - Accessible Rich Internet Applications. 
    It's a specification that enhances accessibility for dynamic content and UI (User Interface) 
    components.

=> WCAG provides general guidelines for web accessibility
=> WAI-ARIA offers specific rules for making dynamic and interactive content accessible for 
    users of assistive technologies.

=> WAI-ARIA works by introducing a set of attributes you can add to HTML elements to provide 
    additional semantic information. 
    These attributes are categorized into roles, states, and properties.

=> ARIA role defines the purpose of an element within a website or web app.
Example: <div role="button">Click Me</div>

ARIA properties provide additional details about elements.

Example:
<h2 id="header-id">About freeCodeCamp</h2>
<button id="button-id" aria-labelledby="header-id button-id">Learn More</button>

=> ARIA stands for Accessible Rich Internet Applications. ARIA roles specify the semantic meaning 
    of HTML elements. 
    They're essential for making web content accessible to people who use assistive technologies, 
    like screen readers.

    - To specify the ARIA role of an element, you just need to add the role attribute, 
        like this role="ARIA role", where value is the name of a role in the ARIA specification.
=> There are six main categories of ARIA roles:
    = Document structure roles 
        => Document structure roles define the overall structure of the web page. Relationships 
            between different sections and help users navigate the content. Most of the document 
            structure roles are not used in modern web development because browsers already support
            equivalent semantic HTML elements, which should be prioritized whenever possible.
    = Widget roles
        => Widget roles define the purpose and functionality of interactive elements, like scrollbars.
            Include scrollbar, searchbox, separator (when focusable), slider, spinbutton, switch, tab, 
            tabpanel, and treeitem.
    = Landmark roles
        => Landmark roles classify and label the primary sections of a web page. Screen readers use 
            them to provide convenient navigation to important sections of a page. You should use 
            them sparingly to keep the overall layout simple and easy to understand. Roles are banner, 
            complementary, contentinfo, form, main, navigation, region, and search.
    = Live region roles
        => Live region roles define elements with content that will change dynamically. Screen readers
            and other assistive technologies can announce changes to users with visual disabilities. 
            These roles include: alert, log, marquee, status, and timer.
    = Window roles
        => Window roles define sub-windows, like pop up modal dialogues. These roles include 
            alertdialog and dialog.
    = Abstract roles
        => These roles help organize the document. They're only meant to be used internally by the 
            browser, not by developers.

Example: <div class="alert" id="exp-warning" role="alert">
            <span class="hidden">Your log in session will expire in 3 minutes.</span>
        </div>

        <div role="math" aria-label="x squared + y squared = 3">
            x<sup>2</sup> + y<sup>2</sup> = 3
        </div>

        <div class="search-container" role="search">
            <label for="searchbox" class="visually-hidden">Search</label>

            <div
                id="searchbox"
                class="searchbox"
                role="searchbox"
                aria-label="Search the site"
                tabindex="0"
                contenteditable="true">
            </div>

            <button type="button" aria-label="Submit search">Search</button>
        </div>

        <div role="banner" class="site-banner">
            <h1>Accessible Web Design</h1>
            <nav>
                <ul>
                <li><a href="#">Home</a></li>
                <li><a href="#">Articles</a></li>
                <li><a href="#">About</a></li>
                <li><a href="#">Contact</a></li>
                </ul>
            </nav>
        </div>

        <div class="status-demo">
            <button id="update-status-btn">Check Status</button>
            <div id="status-msg" role="status" class="status-message">
                No updates yet.
            </div>
        </div>

        <button id="open-dialog">Open Dialog</button>
        <div id="custom-dialog" role="dialog" aria-modal="true" aria-labelledby="dialog-title" class="dialog">
            <div class="dialog-content">
                <h3 id="dialog-title">Confirm Action</h3>
                <p>Are you sure you want to delete this file?</p>
                <div class="dialog-actions">
                    <button id="confirm-btn">Yes</button>
                    <button id="close-dialog">Cancel</button>
                </div>
            </div>
        </div>
